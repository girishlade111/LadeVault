# Phase 6: Build & Deployment — CryptPad v2026.5.1

## 1. Build Pipeline

### Build Steps (`npm run build` → `node scripts/build.js`):
1. **Read config** via `lib/load-config.js`
2. **Clear temp dir** (`os.tmpdir()/CRYPTPAD_TEMP_BUILD/`)
3. **Generate index.html for each app** (22 apps):
   - Injects Open Graph meta tags (og:title, og:description, og:image, og:url)
   - Injects twitter:card meta tag
   - Generates noscript fallback in all available translations
   - Adds version query strings to pre-loading.js and pre-loading.css
   - Validates output: checks for noscript tag, pre-loading references
4. **Generate special pages**: register/, login/, contact.html, features.html, index.html
5. **Copy** from temp dir to `customize/` directory
6. **Clean up** temp dir

### Worker Bundle (`npm run api` → `rollup -c`):
- **Input**: `src/worker/store.ts` (TypeScript)
- **Outputs**:
  - `www/common/worker.bundle.js` (unminified, beautified)
  - `www/common/worker.bundle.min.js` (minified)
- **Plugins**: TypeScript compiler, CommonJS converter, node-resolve, JSON loader, terser
- **Format**: UMD (Universal Module Definition)
- **Target**: ES2015

### Copy Components (`npm run install:components`):
- `scripts/copy-components.js` — copies bower-like frontend dependencies into `www/common/`

### No Webpack:
CryptPad does NOT use Webpack for main application bundling. It uses AMD/RequireJS for client-side module loading with individual script tags per app. The only Rollup bundle is the Web Worker.

### Build Triggers:
| Command | Description |
|---------|-------------|
| `npm run build` | Generate index.html with OG tags, noscript |
| `npm run api` | Build worker bundle via Rollup |
| `npm run install:components` | Copy frontend components |
| `npm start` | Node server.js (run in production) |
| `npm run dev` | DEV=1 node server.js (development mode) |
| `npm run fresh` | FRESH=1 + delete all cached data |

## 2. Deployment Options

### Bare Metal (Linux):
1. Install Node.js 18+ LTS
2. `git clone` and `cd cryptpad`
3. `npm install --production`
4. `npm run install:components`
5. `npm run build`
6. `npm run api` (for worker bundle)
7. Copy `config/config.example.js` → `config/config.js`
8. Edit `config.js` (storage paths, http address, CSP, admin keys)
9. `npm start`

### Docker Deployment:
- **Dockerfile** (58 lines, multi-stage):
  - Stage 1 (build): `node:lts-alpine` — installs deps, patches config
  - Stage 2 (runtime): `node:lts-alpine` — creates non-root `cryptpad` user (UID 4001), copies app
  - Healthcheck: `curl -f http://localhost:3000/`
  - Exposed ports: 3000 (main), 3003 (safe)
  - Volumes: `blob/`, `block/`, `customize/`, `data/`, `datastore/`
  - Entrypoint: `docker-entrypoint.sh`
- **docker-entrypoint.sh**:
  - Installs npm deps if `node_modules` missing
  - Runs `npm run install:components`
  - Runs `npm run build`
  - Runs `npm run api`
  - Starts with `npm start`

### Docker Compose:
```yaml
services:
  cryptpad:
    build: .
    ports:
      - "3000:3000"
      - "3003:3003"
    volumes:
      - ./blob:/cryptpad/blob
      - ./block:/cryptpad/block
      - ./customize:/cryptpad/customize
      - ./data:/cryptpad/data
      - ./datastore:/cryptpad/datastore
    environment:
      - NODE_ENV=production
```

## 3. Port Configuration

| Port | Default | Purpose |
|------|---------|---------|
| 3000 | 3000 | Main HTTP server (app) |
| 3003 | 3003 | Safe HTTP server (CSP-disabled, for sframe) |

The two-port architecture:
- Port **3000**: Serves main pages with full CSP headers
- Port **3003**: Serves sandboxed iframe content with minimal CSP (required for sframe sandbox to work)
- Both must be accessible in browser; they can share the same origin if CSP is configured appropriately

## 4. Directory Layout for Production

```
cryptpad/
├── config/config.js        # Instance configuration
├── customize/               # Customization output (generated by build)
├── blob/                    # Encrypted file uploads
├── block/                   # Encrypted document snapshots
├── datastore/               # Channel data (operations log)
├── data/                    # Pins, metadata, access logs
├── node_modules/            # Dependencies
└── (source files)
```

### Data Persistence (in Docker):
| Directory | Content | Growth Pattern | Backup Strategy |
|-----------|---------|---------------|-----------------|
| `datastore/` | Channel NDJSON logs | ~100 MB/1000 active pads | Frequent (source of truth) |
| `blob/` | Encrypted file uploads | Unbounded (user files) | Periodic |
| `block/` | Snapshot blocks | Bounded by user activity | Periodic + snapshot |
| `data/` | Pins, metadata | Small | Frequent |
